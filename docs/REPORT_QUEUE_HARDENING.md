# 運営通報管理のローカル再検証（2026-10-21）

## 修正と確認
- P2修正: getSession待機中のログイン切替で、旧tokenの通信が新しい世代として扱われる経路を閉じた。操作開始を最初のawaitより前に記録し、認証後・応答後・例外・finallyの全箇所で照合する。
- P2修正: 同じ描画フレーム内の二重操作を同期refで拒否。認証変更とunmountで実行中操作を無効化し、古いfinallyで新しい操作のbusyを解除しない。
- 送信済み操作は画面無効化だけでは取消できない。DBの認可チェック・退会ロックが最終境界。権限取消より先にロックを得て確定した操作は有効な監査として残る。
- 非運営、JWT不一致、一般authenticatedによる直接RPC、退会中運営を拒否。権限取消・退会後は過去成功IDの再送も拒否する。
- 同一受付の二番目の担当者は上書き不可。同一request/同一内容の再送は1件に収束し、内容相違・別操作のID流用は拒否。
- 非表示と監査の途中失敗・transaction rollback・SQLSTATE 57014キャンセルで解決記録が残らず、同一IDで再試行可能。通常書込停止の解除やSQL変更は追加していない。
- UIは実TSXを変換してhook/認証/fetchを制御するオフラインハーネスで検証。実ブラウザE2Eではない。

## 検証の限界
PGliteは1接続。複数担当者の順次実行と失敗注入は検証できたが、実際の待機・デッドロック・別接続の可視性を証明しない。
ローカルにpostgres/pg_ctl/dockerが見つからないため、別接続試験は未実施。実Supabase・本番ユーザーデータへの接続なし。
一覧の件数と行はREAD COMMITTEDの別SELECTなので、並行対応時に一時的な差があり得る。更新して確認する。常時監視ではない。
