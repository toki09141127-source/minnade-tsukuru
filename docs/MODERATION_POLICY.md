# 100人MVPのモデレーション運用案

Status: USER APPROVAL REQUIRED。公開ポリシーの確定ではない。

## 現状と不足

通報UIとPOST /api/reports/createは存在し、Bearer本人確認/理由必須がある。今回理由2000文字上限とflag有効時5件/分を追加。通報を送れたことと運営が対処できることは別。管理者専用の審査/BAN/異議申立ての完了導線は未確認で公開合格に数えない。

## 公開前の必須運用

- 担当者・代理・実在する連絡先・受付時間/応答目安を決める。緊急危害/個人情報/違法性疑義/権利侵害を優先する。
- 審査権限は一般ユーザーのroleと分離。Service Role keyをブラウザに配布しない。操作を対象ID/担当/理由/時刻で監査する。
- 暫定非表示を優先し、証拠と共同作品への影響を確認して削除を決定。ルーム・投稿・作品・添付署名で同じ非表示判定を適用。
- 繰返し悪用へのアカウント停止/解除を用意。session失効とAPI/DB直接アクセスの拒否をstagingで確認。UIだけのBAN不可。
- 当事者通知、異議申立て受付、別担当再審査、復旧の手順を用意。申告者の個人情報は不要に共有しない。
- 合成fixtureで通報→審査→非表示→署名不可→異議→復旧を通す。削除を実ユーザーデータで練習しない。

100人なら人手審査中心でよいが、担当/窓口/停止手順がない状態では募集しない。自動分類、大規模審査queue、AIによる判定は将来対応。AIに確定処分を委ねない。正式文面と削除/BAN権限設計は別承認。
## 具体的な推奨運用案（2026-10-21）

MVP_RETENTION_MODERATION_RECOMMENDATION.mdに、退会/作品/名義/期間/通報/異議/検収の推奨案を作成。未採用・未公開。毎日2回確認する責任者と代理、24時間一次確認/通常72時間初回判断を内部目標とする案。緊急案件は発見次第暫定非表示。14日異議窓口は法的請求を制限しない。実在窓口と対応可能時間の確定が必要。
今回のコードでは非表示/削除post/roomへの重要マーク操作を拒否し、postが更新直前に非表示/削除/別roomへ移動した場合もUPDATEと競合readに条件を追加した。room/membership確認とUPDATEは別transactionなので、room非表示/退室との競合を完全に解消したものではない。実DB権限修正/atomic化が別途必要。
